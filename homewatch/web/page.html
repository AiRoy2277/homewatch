封禁名单

封禁响应

444 不回任何字节直接断开，扫描器只能看到超时；「不写日志」需要站点 access_log 挂条件，点应用时会自动改。

为什么要封两层

走 Cloudflare 进来的流量，nft 看到的是 CF 的 IP，在网络层封攻击者无效；应用层（nginx）能看到还原后的真实 IP，两层一起封才干净。

面板登录

修改面板密码

访问本面板管理接口的登录密码（用户名固定 admin），和 root 密码不是一回事。改完当前页面会要求重新登录；忘记后只能从 PVE Console 删掉密码文件再用 deploy 重新生成。

安全建议

面板只监听内网，公网到不了；basic auth 只挡人不挡扫描。 建议定期换一次密码，长度 12 位以上、三类字符。 root 密码改动会影响 SSH 登录，别和面板密码用同一个。

策略规则

按置信度从高到低评估
窗口 = 统计最近多少秒（按整分钟对齐）；阈值 = 窗口内命中多少次触发；时长 = 封禁小时数（0 表示永久，会被上限截断）；层 = 下发到哪一层。 同一 IP 在复发窗口内再次触发，时长翻倍。单次评估最多封上限个数，命中多条时按置信度从高到低排。

手动评估

点「演练一次」看看当前会封哪些 IP，只看不封。确认没问题再点「立即执行」。
