WHY

公网暴露的机器每天被扫几千次
但你只需要关心三件事

大多数监控面板给你的是"请求数曲线"。那条线一直在动，却回答不了"我到底有没有事"。 HomeWatch 反过来：先把这三件事做成一眼能看的红黄绿，细节再往下钻。

01

有没有东西真的被读走了

不是"被请求了"，是"返回了真实内容"。200 且带内容才算数，404 和拦截回包不算。

判断依据：响应码 + 响应体大小
02

是不是正在被打

现在这一刻的强度。近 10 分钟的量级放在最上面，红黄绿三档阈值可自己调。

判断依据：近 10 分钟请求与拦截
03

打了多久、从哪来、在找什么

用于判断是不是同一批人又回来了。来源表按 IP 聚合，点开是完整档案：UA、路径、时间轴。

判断依据：历史窗口 + IP 档案

FEATURES

该有的都有，不该有的一个没有

增量采集，不重读日志

按 inode + 偏移量接着上次读，日志轮转后自动重新定位。一分钟一次，CPU 占用可以忽略。

四道闸门，逐条可关

蜜罐路径、报文异常（超长 URL / 超大 body / 怪方法 / 坏 UA）、单 IP 频率、拦截洪水。阈值和时间窗都在配置里。

封禁同时落三层

nft 管直连和 SSH，nginx map 管 HTTP，CF 管边缘。面板上每一处出现 IP 的位置都带「已封禁」标记，没封的旁边就是一键封。

有序防火墙规则表

不是一堆散落的 iptables 命令，是一张能增删改查、能看命中计数的有序表。容器转发链自动镜像同样的策略。

地域封锁，两把开关

用国内网段集合判定境外来源，一次哈希出结果。外来和对外分开管：外来可只挡 Web 端口，对外先放行已建立连接。

进程守护与端口开关

哪些端口在听、哪个进程在跑、该在的还在不在。关端口、切 SSH 端口（带自动回滚）、改密码都能在页面上点。

GEO BLOCK

境外 IP 自动识别
外来和对外分开

不查归属地库、不等接口返回：把国内网段做成 nft 集合，来一个包做一次哈希查找就判完了。

QUICK START

先本地跑一遍，再决定要不要装

本地模式用 HOMEWATCH_ROOT 把所有路径重定向到沙箱目录，不碰 /var/lib、不碰 nftables。

终端 
# 1. 拿代码
git clone https://github.com/AiRoy2277/homewatch.git
cd homewatch

# 2. 环境自检（缺什么会直接说）
python hw.py doctor

# 3. 沙箱里跑一遍，看面板长什么样
HOMEWATCH_ROOT=./.test python hw.py -c config.example.json run
python hw.py status
部署到服务器 
# 需要 root 的 SSH
pip install paramiko

export HOMEWATCH_HOST=192.168.1.10
SSH_PW='你的密码' python deploy/deploy.py push
# install 首次安装：装定时器、生成面板凭据、
# 更新 nginx 站点、把 nftables 升级成集合结构
SSH_PW='你的密码' python deploy/deploy.py install
SAFETY

会封别人的东西
先想清楚怎么不封自己

4 分钟自动回滚保险丝

首次升级 nftables 时挂一个定时器，改完没确认就自动恢复原规则。SSH 被锁也能自己回来。

没有网段清单就拒绝开启

国内清单还没拉下来时开地域封锁，!= @cn4 会恒真把所有来源挡掉。后端直接报错，不写状态。

境外操作会被拦住

从面板开外来封锁时，如果请求来源本身就是境外且不在豁免里，直接报错并给出服务器上该执行的命令。

封禁是静默的

默认回 444 直接断开，扫描器拿不到任何回包，也就不知道是被封了还是没这个站。

自己的机器，自己看得见

不需要云服务、不需要账号、不上传任何数据。一台机器、一个 Python 解释器、一个 nginx，就够跑起来。
